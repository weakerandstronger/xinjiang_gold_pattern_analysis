你现在的任务是：根据我提供的两个 JSON 输入文件（schema.json 和 doc.json），从单篇地质文献中抽取“新疆金矿床知识图谱”相关的实体和关系，并输出一个符合指定结构的 output.json。

⚠ 总要求（务必遵守）：
1. 你最终的回答 **必须只包含一个 JSON 对象**，不要输出任何解释性文字、注释或额外内容。
2. 输出 JSON 必须符合我在「三、输出 JSON 结构要求」中给出的结构。
3. 所有实体名称、属性值、关系标签、关系描述，一律使用 **中文**。
4. JSON 中不允许出现注释符（如 `//`、`#` 等），必须是合法 JSON。

------------------------------------------------
二、抽取任务说明
------------------------------------------------

你需要输出一个 JSON，其中包含两大部分：

1）`kg_instances` —— 严格符合 schema 的实体和关系，用于直接构图

2）`schema_new` —— 本篇文献中新发现但当前 schema 中不存在的实体类型 / 属性 / 关系类型 / 关系属性建议，仅供人工后续更新 schema 时参考

--------------------------------
2.1 抽取实体（进入 kg_instances.entities）
--------------------------------

1. 在 doc.json 的所有 blocks[*].text 中，识别与新疆金矿床相关的实体，例如：
   - 矿床（Deposit）
   - 区域/成矿带（Region）
   - 地层单元（StratUnit）
   - 赋矿岩石单元（HostRockUnit）
   - 岩性（Lithology）
   - 构造（Structure）
   - 蚀变（Alteration）
   - 矿物（Mineral）
   - 成矿流体（Fluid）
   - 同位素参数（Isotope）
   - 地球物理异常（Geophysics）
   - 地球化学数据（Geochem）
   等。

2. 对于每个实体：
   - 选择 `entity_type`：必须是 schema.json 的 `entity_schema` 中的某个键，比如 "Deposit"。
   - 生成 `entity_local_id`：在本篇文献内部唯一，例如 "E1", "E2", "E3", ...
   - 生成 `name_zh`：该实体的中文名称（如果原文是英文，需要翻译为合适的中文地学术语）。
   - 生成 `attributes`：这是一个键值对对象，其中：
     - 键（attribute key）必须是对应实体类型 `key_attributes` 里定义的英文键名，如 Deposit 的 "name", "location", "deposit_type", ...
     - 值必须为中文描述，例如 `"location": "新疆东准噶尔地区"`。
   - 不要使用 schema 中不存在的属性键；如需要新属性，放入后面 `schema_new.new_entity_attributes` 中，而不是直接加到 `kg_instances.entities[*].attributes`。

3. 在单篇文献内部，尽量将同一个事物（如同一矿床）合并为一个实体，避免重复。

--------------------------------
2.2 抽取关系（进入 kg_instances.relations）
--------------------------------

1. 在 doc.json 的 blocks[*].text 中，识别实体之间的关系，限定为 schema.json 中 `relation_schema` 里列出的关系类型。

2. 对于每条关系：
   - `relation_type`：必须是 schema.json 中 `relation_schema[*].id` 的某个值，如 "Deposit-Region", "Deposit-Lithology"。
   - `relation_local_id`：在本篇文献内部唯一，例如 "R1", "R2", "R3"。
   - `from_entity_local_id` 和 `to_entity_local_id`：
     - 必须引用 `kg_instances.entities` 中已有的 `entity_local_id`；
     - 且对应实体的 `entity_type` 必须等于该关系类型在 schema.json 中定义的 `from_entity` 和 `to_entity`。
   - `relation_label_zh`：该关系的中文表达，如 "位于"、"隶属于"、"主要赋存于"、"受…控制" 等。
   - `description`：用中文简要描述该关系的具体含义，例如：
     - `"卡拉麦里金矿床位于东准噶尔成矿带中部"`。

3. 不要在 `kg_instances.relations` 中使用 schema.json 中不存在的关系类型或关系属性；如需要新关系类型或新属性，请放到 `schema_new` 中。

--------------------------------
2.3 发现 schema 外的新内容（进入 schema_new）
--------------------------------

如果在文献中遇到下列情况，请不要直接写入 `kg_instances`，而是记录在 `schema_new` 中，供人工后续更新 schema.json 使用：

1. 新的实体类型建议（schema_new.new_entity_types）：
   - 当文献中多次提到某种概念（例如“矿化分带”、“矿化阶段”等），而目前 `entity_schema` 中没有对应的实体类型时；
   - 为其构造一个建议条目，包含：
     - `suggested_type_id`：建议的英文类型 ID，例如 "MineralizationZone"；
     - `cn_name`：中文名称；
     - `description`：中文描述；
     - `example_mentions`：文中体现这一概念的中文句子或短语（可以给 1~3 个代表性的例子）。

2. 新的实体属性建议（schema_new.new_entity_attributes）：
   - 当文献在某个实体类型上反复提到一个属性，而该属性不在该实体类型的 `key_attributes` 列表中时；
   - 为其构造一个建议条目，包含：
     - `entity_type`：已有的实体类型，例如 "Deposit"；
     - `suggested_attr_id`：建议的属性英文键名，例如 "exploration_degree"；
     - `cn_name`：属性中文名称，例如 "勘查程度"；
     - `description`：中文描述；
     - `example_values`：文中出现的该属性的一些典型中文取值。

3. 新的关系类型建议（schema_new.new_relation_types）：
   - 当文献描述了某种关系，而 `relation_schema` 中不存在对应的关系类型时；
   - 为其构造一个建议条目，包含：
     - `suggested_id`：建议的关系类型 ID，例如 "Deposit-Deposit"；
     - `from_entity` 和 `to_entity`：建议连接的实体类型，例如 "Deposit" 到 "Deposit"；
     - `cn_name`：中文名称；
     - `description`：中文描述；
     - `relation_label_examples`：文本中可能出现的中文关系表达；
     - `example_mentions`：文中特定句子或片段作为例证。

4. 新的关系属性建议（schema_new.new_relation_attributes）：
   - 当某个已存在的关系类型，在文献中出现了新的、定量或定性的关系属性（但当前 schema 未定义）时；
   - 为其构造一个建议条目，包含：
     - `relation_type`：已有的关系类型 ID，例如 "Deposit-Region"；
     - `suggested_attr_id`：建议的属性英文键名，如 "distance_to_boundary"；
     - `cn_name`：中文名称，如 "距构造边界距离"；
     - `description`：中文描述；
     - `example_values`：文中的典型中文取值。
