你是一名具有**矿床学、区域成矿学、矿床成矿区带划分、构造地质学、区域地质学和地质知识图谱**研究经验的专家。

我正在构建**新疆金矿床知识图谱**。目前已经从全部矿床数据中提取出 `Region（矿床区域/成矿区带）` 特征的**完整唯一值列表**。

这些数据来自不同地质文献，不同作者对同一或相关区域可能采用不同的：

-  区域名称； 
-  成矿带名称； 
-  金矿带名称； 
-  矿集区名称； 
-  构造带名称； 
-  造山带名称； 
-  盆地名称； 
-  地区名称； 
-  空间层级； 
-  方位限定； 
-  矿种组合； 
-  标点及连接符形式。 

因此，需要建立统一的 `Region` 受控词表（controlled vocabulary）。

后续标准化结果将用于：

-  金矿床区域分布统计； 
-  Jaccard similarity； 
-  Support； 
-  Lift； 
-  区域—矿物—蚀变—地球化学共现分析； 
-  跨特征高阶共现模式挖掘； 
-  金矿床勘查标识分析； 
-  知识图谱区域关联分析。 

标准化必须遵循：

> **消除同一地质区域因文字形式、冗余限定和非规范写法造成的差异，但必须保留不同空间层级、不同成矿区带和不同构造单元之间真实的地质差异。**

特别强调：

> **空间包含关系不等于语义等价关系。**

例如：

```
西准噶尔地区
```

西准噶尔成矿带

西准噶尔哈图成矿带

哈图成矿带

可能存在空间隶属或包含关系，但不能仅根据字符串相似性直接合并为同一个标准值。

---

# 一、首先识别区域实体类型

当前 `Region` 数据实际上可能混合多种区域实体类型，包括：

### 1. 成矿带

例如：

```
额尔齐斯成矿带
```

西天山成矿带

西准噶尔成矿带

阿尔金成矿带

### 2. 金矿带

例如：

```
卡拉麦里金矿带
```

康古尔塔格金矿带

萨吾尔金矿带

哈巴河金矿带

### 3. 多金属成矿带

例如：

```
北山金-铜多金属成矿带
```

西天山博罗科努铜钼金多金属成矿带

### 4. 矿集区

例如：

```
包古图金—铜矿集区
```

哈图金矿集区

### 5. 构造带 / 造山带

例如：

```
阿尔泰造山带
```

南天山构造带

西南天山造山带

### 6. 盆地 / 裂谷

例如：

```
吐拉苏盆地
```

克兰弧后盆地

哈巴河弧间盆地

雅满苏裂谷

### 7. 地区

例如：

```
西准噶尔地区
```

阿拉塔格地区

库鲁克塔格地区

### 8. 空间分段或边缘区域

例如：

```
东准噶尔阿尔曼泰构造带东段
```

准噶尔盆地西缘

阿尔泰造山带南缘西段

这些实体属于不同地质空间粒度。

因此：

> **不得把“地区”“成矿带”“构造带”“矿集区”“盆地”等不同类型仅因地名相同而直接合并。**

---

# 二、标准化的核心粒度

本任务原则上采用：

> **一个具有明确区域地质或成矿学意义的空间单元 = 一个 canonical value**

例如：

```
卡拉麦里金矿带
```

额尔齐斯成矿带

西准噶尔成矿带

阿尔泰造山带

吐拉苏盆地

哈图金矿集区

分别属于独立标准值。

---

# 三、严格禁止按空间包含关系进行合并

这是本任务最重要的规则之一。

例如：

```
西准噶尔地区
```

西准噶尔成矿带

西准噶尔哈图成矿带

不能全部标准化为：

```
西准噶尔
```

因为它们可能代表：

-  广义地理区域； 
-  成矿区带； 
-  更低一级成矿带。 

同样：

```
阿尔泰造山带
```

阿尔泰造山带南缘西段

中国阿尔泰造山带南缘西段

其中前两个不是同一个空间尺度。

不能将：

```
阿尔泰造山带南缘西段
```

直接并入：

```
阿尔泰造山带
```

因为“南缘西段”是有地质意义的空间限定。

---

# 四、可以统一纯文字冗余的区域名称

如果两个表达实际上指向同一个区域实体，仅存在明显的语言冗余，可以 MERGE。

例如：

```
中国阿尔泰造山带南缘西段
```

阿尔泰造山带南缘西段

如果经区域地质语义判断确认二者指向同一地质单元，则可以统一为：

```
阿尔泰造山带南缘西段
```

其中：

```
中国
```

只是国家级上下文，不改变该区域实体本身。

输出示例：

```
{
```

  "raw\_value": "中国阿尔泰造山带南缘西段",

  "canonical\_values": ["阿尔泰造山带南缘西段"],

  "action": "MERGE",

  "modifier": null,

  "confidence": 0.96,

  "reason": "国家限定不改变区域实体"

}

但如果无法确认是否完全对应：

```
action = REVIEW
```

优先于强制归并。

---

# 五、地名相同但区域类型不同，不能合并

例如：

```
卡拉麦里金矿带
```

卡拉麦里成矿带

虽然核心地名均为：

```
卡拉麦里
```

但是：

```
金矿带
```

成矿带

并不天然严格等价。

除非有充分区域成矿学依据确认二者在相关文献中实际指向同一个区域单元，否则应分别保留或标记 REVIEW。

同样：

```
萨吾尔金成矿带
```

萨吾尔金矿带

不能仅根据字符串相似性直接合并。

---

# 六、“金矿带”与“金成矿带”不能机械统一

例如：

```
萨吾尔金矿带
```

萨吾尔金成矿带

可能在部分文献中指同一成矿区带，但两个术语并不在所有情况下严格等价。

因此：

1.  如果区域地质文献中明确为同一正式区域单元，可以 MERGE； 
2.  如果仅凭当前唯一值列表无法确认，应 REVIEW； 
3.  不能只因为多了“成”字就自动合并。 

---

# 七、“地区”不能自动转化为“成矿带”

例如：

```
西准噶尔地区
```

不能因为列表中同时存在：

```
西准噶尔成矿带
```

就自动转换为：

```
西准噶尔成矿带
```

因为“地区”可能仅表示地理范围，而“成矿带”是成矿区划单元。

同样：

```
阿拉塔格地区
```

库鲁克塔格地区

应保留其区域层级。

---

# 八、构造单元与成矿单元必须严格区分

例如：

```
南天山构造带
```

西南天山造山带

西南天山成矿带

三个名称虽然具有明显空间关联，但分别属于：

-  构造单元； 
-  造山带； 
-  成矿区带。 

不得互相合并。

同样：

```
雅满苏裂谷
```

阿齐山—雅满苏铁铜金成矿带

不能因为均含“雅满苏”就归并。

---

# 九、盆地、裂谷和岛弧不能转化为成矿带

例如：

```
吐拉苏盆地
```

克兰弧后盆地

哈巴河弧间盆地

雅满苏裂谷

博罗科努古生代复合岛弧带

这些属于构造—地理单元。

必须分别保留。

不能根据它们与金矿床的关系将其修改成：

```
吐拉苏成矿带
```

克兰成矿带

等输入数据中不存在的名称。

---

# 十、方位和空间分段必须保留

例如：

```
东准噶尔阿尔曼泰构造带东段
```

准噶尔盆地西缘

阿尔泰造山带南缘西段

其中：

```
东段
```

西缘

南缘西段

均属于具有空间意义的限定。

不能为了减少标准词数量而删除。

例如：

```
阿尔泰造山带南缘西段
```

不能标准化为：

```
阿尔泰造山带
```

---

# 十一、上级区域前缀不能轻易删除

例如：

```
东天山康古尔塔格金矿带
```

康古尔塔格金矿带

从文字看，前者多了：

```
东天山
```

但不能直接假设二者完全等价。

需要判断：

-  “东天山”是否只是对康古尔塔格金矿带所在大区的定位； 
-  还是正式区域名称的一部分； 
-  两者是否在原文中确实指向完全相同的空间单元。 

如果无法确认：

```
REVIEW
```

优先。

同样适用于：

```
西准噶尔哈图成矿带
```

哈图成矿带

---

# 十二、矿种组合的标点形式应统一

区域名称中存在：

```
金-铜
```

金—铜

金铜

金、铜

铜金

铜-金

等表达形式。

首先应判断它们是否属于正式区域名称中的矿种组合。

如果同一个区域仅因连接符不同，例如：

```
A金-铜成矿带
```

A金—铜成矿带

可以统一连接符。

建议受控词表统一使用：

```
-
```

例如：

```
金-铜
```

铜-钼-金

但：

> **矿种排列顺序不同不能仅根据文字形式自动认为名称相同。**

如果涉及正式成矿区带名称，应以规范区域名称为准。

---

# 十三、统一连接符和标点

统一以下连接符：

```
—
```

−

–

\-

原则上统一为：

```
-
```

例如：

```
哈图−萨尔托海金矿带
```

可以规范为：

```
哈图-萨尔托海金矿带
```

类似：

```
大山口—萨恨托尕金成矿亚带
```

可规范为：

```
大山口-萨恨托尕金成矿亚带
```

只改变符号形式，不改变地质含义。

---

# 十四、“矿床名称”和“区域名称”不能混淆

如果某个词实际上是具体矿床，而不是区域单元，应谨慎处理。

本字段应该表达：

```
Region
```

而不是：

```
Deposit
```

如果发现某个 raw value 明显是具体矿床名称，应：

```
action = REVIEW
```

不能因为它出现在 Region 列中就强行添加：

```
地区
```

成矿带

矿集区

等后缀。

---

# 十五、矿集区和成矿带不能强制归并

例如：

```
包古图金-铜矿集区
```

包古图金铜成矿带

虽然均包含：

```
包古图
```

金

铜

但：

```
矿集区
```

成矿带

代表不同的成矿空间概念。

因此不能仅根据词语相似性进行 MERGE。

原则上应：

```
KEEP
```

或者在无法判断时：

```
REVIEW
```

---

# 十六、“成矿亚带”应保留其层级

例如：

```
大山口-萨恨托尕金成矿亚带
```

其中：

```
成矿亚带
```

代表相对低一级的区域成矿单元。

不能改成：

```
大山口-萨恨托尕金成矿带
```

更不能归入上一级区域。

---

# 十七、同名区域不同层级必须同时允许存在

最终 canonical vocabulary 可以同时存在：

```
阿尔泰造山带
```

阿尔泰造山带南缘西段

也可以同时存在：

```
西准噶尔地区
```

西准噶尔成矿带

西准噶尔哈图成矿带

这是正常现象。

标准词数量多并不意味着标准化失败。

本任务目标是：

> **消除真正的重复，而不是强行减少词汇数量。**

---

# 十八、区域层级信息不能因后续统计而过度简化

后续虽然需要计算：

```
Jaccard similarity
```

Support

Lift

但不能为了提高共现率而把所有区域压缩到大的地理单元。

例如：

```
哈图金矿集区
```

哈图成矿带

西准噶尔哈图成矿带

如果它们并非严格同一空间实体，应保留。

否则会人为放大区域特征的 Support。

---

# 十九、不建立额外的父级区域

例如输入中存在：

```
阿尔泰造山带南缘西段
```

不能自行补充：

```
阿尔泰造山带南缘
```

除非它本身出现在输入数据或有明确任务要求。

同样：

```
准噶尔盆地西缘
```

不能因此自动增加：

```
准噶尔盆地
```

本任务是：

> **区域术语标准化，不是区域层级知识补全。**

---

# 二十、`null` 的处理

`null` 表示区域信息缺失。

必须输出：

```
{
```

  "raw\_value": "null",

  "canonical\_values": [],

  "action": "MISSING",

  "modifier": null,

  "confidence": 1.0,

  "reason": "缺失值，不进入标准词表"

}

注意：

> `null` 仅表示原数据未记录 Region，不能解释为矿床不存在区域归属。

---

# 二十一、允许的标准化操作

每个 raw value 只能选择以下一种 action。

## KEEP

原词已经是规范且粒度合适的区域名称。

例如：

```
额尔齐斯成矿带
```

阿尔泰造山带

吐拉苏盆地

---

## MERGE

两个表达明确指向同一个区域实体，仅存在：

-  非规范连接符； 
-  冗余国家限定； 
-  明确的异体写法； 
-  可确认的同义名称。 

例如：

```
哈图−萨尔托海金矿带
```

可以规范为：

```
哈图-萨尔托海金矿带
```

---

## MERGE\_WITH\_MODIFIER

只有当原始值中存在不属于核心区域名称、但仍需要保存的上下文信息时使用。

Region 数据一般较少使用这一操作。

例如确有：

```
研究区某成矿带
```

且“研究区”只是文献上下文时，可考虑剥离。

但不能用 modifier 删除：

```
东段
```

西缘

南缘

西段

等真正的空间限定。

---

## SPLIT

Region 特征原则上**极少使用 SPLIT**。

只有当 raw value 明确同时列出两个独立区域实体时才能拆分。

例如：

```
A成矿带、B成矿带
```

并明确表示两个独立区域时，可以 SPLIT。

但：

```
哈图-萨尔托海金矿带
```

是一个复合命名区域，不得拆成：

```
哈图金矿带
```

萨尔托海金矿带

---

## REVIEW

以下情况优先 REVIEW：

-  名称相似但无法确认是不是同一区域； 
-  金矿带与成矿带是否等价不明确； 
-  上级区域前缀是否只是定位信息不明确； 
-  同一地名对应不同区域层级； 
-  正式区域名称规范形式无法确定； 
-  疑似具体矿床而非区域； 
-  是否属于同一个成矿区划单元存在疑问。 

---

## MISSING

仅用于：

```
null
```

---

# 二十二、Region 标准化中禁止的行为

禁止：

1.  根据字符串相似度直接合并； 
2.  根据空间包含关系直接合并； 
3.  把子区域统一为父区域； 
4.  把父区域统一为子区域； 
5.  把“地区”自动变为“成矿带”； 
6.  把“构造带”自动变为“成矿带”； 
7.  把“造山带”自动变为“成矿带”； 
8.  把“矿集区”自动变为“成矿带”； 
9.  把“金矿带”与“金成矿带”无条件合并； 
10.  删除“东段、西缘、南缘西段”等空间限定； 
11.  根据矿床所在地补充上级区域； 
12.  根据一般区域地质知识增加输入中不存在的 Region； 
13.  为降低标准词数量进行过度归并。 

---

```
[
```

# 二十八、全局一致性复核

第一次映射完成后，请重新检查全部结果。

重点检查：

### 1. 空间层级


### 2. 父子区域

是否错误把子区域并入父区域。

### 3. 方位限定

是否删除：

```
东段
```

西缘

南缘西段

### 4. 相同地名不同类型

例如：

```

```

```

```

东天山康古尔塔格金矿带

是否需要 REVIEW。

### 6. 同名区域

例如：

```
哈图成矿带
```

西准噶尔哈图成矿带

是否在无依据情况下被强制合并。

### 7. 标点

是否统一：

```
—
```

−

–

\-

但没有改变区域含义。

### 8. 矿种组合

是否因：

```

```

金-铜

金—铜

等形式差异产生不必要重复。

### 9. 矿集区与成矿带

是否被错误认为同一区域实体。

### 10. 是否人为增加父级区域

禁止知识补全。
